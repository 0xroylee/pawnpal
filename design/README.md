# pawnpal design kit

The visual system for pawnpal: tokens, components, screens, mascot and assets. Open `kit.html` in a browser to see everything rendered.

| File | What it is |
|---|---|
| `kit.html` | The kit: principles, color, type, board, Pip, components, screens, motion, voice, accessibility, research |
| `tokens.css` | Design tokens as CSS custom properties. The source of truth |
| `tokens.json` | Generated from `tokens.css` for TypeScript (`scripts/build-tokens-json.mjs`) |
| `components.css` | Component styles (`pp-*` classes) the React app reuses |
| `assets/pieces/horsey/` | **Default** piece set by cham and michael1241, **CC BY-NC-SA 4.0** (not GPL; see its `LICENSE.md`) |
| `assets/pieces/pawnpal/` | Friendly piece set (option), ours, GPL-3.0, generated by `scripts/build-pieces.mjs` |
| `assets/pieces/cburnett/` | Classic piece set (option), GPLv2+ (see its `LICENSE.md`) |
| `assets/fonts/` | Nunito variable font, SIL OFL 1.1 |
| `assets/pip/` | Pip the Pawn in 5 expressions, generated by `scripts/build-pip.mjs` |
| `scripts/check-contrast.mjs` | Checks every text and UI color pair against WCAG minimums. Exits 1 on failure |

```bash
node design/scripts/build-pip.mjs          # regenerate Pip SVGs
node design/scripts/build-pieces.mjs       # regenerate the friendly piece set
node design/scripts/build-tokens-json.mjs  # regenerate tokens.json after editing tokens.css
node design/scripts/check-contrast.mjs     # all pairs must pass
```

## Direction

Calm, modern and simple: a warm paper background, white cards, one ink color and a large board. Kid buttons are chunky with a solid 4px edge so they look pressable. Pip speaks only when it matters, and rewards come at the end of a game.

Key rules:
- **Blue means "do this":** the main button and the better-move arrow.
- **Coral/orange means "careful":** the danger ring and the threat arrow.
- **Shape before color:** solid vs dashed arrows, dot vs ring, a "!" badge, and an icon plus a word on every grade.
- **Kid sizes:** 72px buttons (60px secondary), 18px minimum text, 24px coach text, board 600px target (75px squares) and 512px minimum.
- **Two age bands:** the default is 6–8. Profiles aged 9+ get `data-band="older"`, with one step smaller text and buttons, coordinates on, and read-aloud off by default.
- **Parent area looks different:** system font, grey, dense, behind a PIN.
- **Pieces:** horsey by default. Our Pip-style Friendly set and classic cburnett are options. Open `kit.html?pieces=pawnpal` or `?pieces=cburnett` to see the kit with them.

## Changes from the earlier UI proposal

- **Font is Nunito, not Atkinson Hyperlegible.** Atkinson was designed for low-vision adults and makes no child-specific claims. The children's typography research found letterform differences didn't change children's reading performance (Walker). So the choice came down to friendliness and legibility: rounded, open, and a large x-height.
- **Better-move arrow is blue and solid; threat arrow is orange and dashed; both have a white halo.** An orange arrow on a green board can disappear for color-blind kids. The halo and the dash fix that without depending on color.
- **Kid buttons are 72px, not 56px.** NN/g recommends about 2 cm targets for kids.
- **"Give up" moved to the top bar,** away from the bottom edge where kids tap by accident.
- **On portrait tablets, the opponent sits in the top bar and the kid's row holds the Hint button.** That keeps the board at 600px on a 768×1024 screen.

## Research notes

### Children's UX

- **Touch targets:** about 2 × 2 cm, 4× the adult 1 cm; a 5mm close button defeated 7-year-olds.
  - [NN/g: physical development](https://www.nngroup.com/articles/children-ux-physical-development/)
  - Smashing suggests at least 75×75px and 18–19px text: [Smashing 2024](https://www.smashingmagazine.com/2024/02/practical-guide-design-children/)
- **Age bands:** 3–5, 6–8 and 9–12 are different audiences. Kids reject content even one grade too young ("for babies"). Font size: 14pt for young children, 12pt for older ones. [NN/g: usability issues](https://www.nngroup.com/articles/childrens-websites-usability-issues/)
- **Icons and words:** for ages 6–8, icons and imagery are the main way to communicate. Kids read icons literally. [UXmatters 2020](https://www.uxmatters.com/mt/archives/2020/01/ux-design-for-kids-key-design-considerations.php)
- **Input:** dragging is hard for under-9s with a mouse, so allow several input methods (tap-tap and drag). [NN/g](https://www.nngroup.com/articles/children-ux-physical-development/)
- **Sound and affordances:** the app must work with the sound off, and flat design hides what's tappable. [Smashing 2016](https://www.smashingmagazine.com/2016/01/designing-apps-for-kids-is-not-childs-play/)
- **Feedback:** kids want feedback that offers a way forward: another try, the answer, or an explanation (Smashing 2016). Kids are poor at troubleshooting, so prevent errors. [NN/g: cognition](https://www.nngroup.com/articles/kids-cognition/)
- **Praise:** praise effort and process, not intelligence. "You must be smart" made kids avoid challenges (Mueller & Dweck 1998). [Summary](https://progressfocused.com/2020/09/mueller-dweck-1998-classic-study.html)
- **Ads and parent links:** kids can't tell ads from content, and parent links should be placed where kids won't click them. [NN/g](https://www.nngroup.com/articles/childrens-websites-usability-issues/)
- **Nudges:** steer toward wellbeing and avoid manipulative nudges. [ICO Children's Code, standard 13](https://ico.org.uk/for-organisations/guide-to-data-protection/ico-codes-of-practice/age-appropriate-design-a-code-of-practice-for-online-services/13-nudge-techniques)

### Chess apps for kids and beginners

- **Duolingo Chess:**
  - Layout is a single column: coach bust with a speech bubble, a full-width board, and a one-action bottom bar.
  - Review covers key moments only, to avoid information overload: [Duolingo engineering](https://blog.duolingo.com/engineering-game-review/).
  - Its most common complaint is a mascot that repeats the same lines on every puzzle: [review](https://davidwilliamrosales.com/2025/08/18/duolingo-chess-review/).
- **ChessKid:**
  - Merges move labels "to simplify for kids". [ChessKid](https://www.chesskid.com/learn/articles/turn-every-game-into-a-learning-adventure-with-game-review)
  - Has a spin-wheel reward. We skip variable rewards.
- **Chess.com:**
  - Uses 10 move labels plus accuracy and rating, which is the cluttered end of the range.
  - Dr. Wolf's "Are you certain?" after a blunder is the closest precedent for our "Keep my move".
  - Arrow colors: green for a better move, red for a threat. [Support article](https://support.chess.com/en/articles/17665907-what-do-the-colored-arrows-in-game-review-mean)
- **Lichess:**
  - The hint circles the piece first, then draws the arrow. [practiceCtrl.ts](https://github.com/lichess-org/lila/blob/master/ui/analyse/src/practice/practiceCtrl.ts)
  - The Learn mode never gives 0 stars for finishing.
  - There's an open complaint that red and green look the same to color-blind players. [lila #10410](https://github.com/lichess-org/lila/issues/10410)

### Assets and libraries

- **react-chessboard 5.12.1** (MIT, React 19):
  - Arrows support a color per arrow, but width and opacity are global and there's no dashed style. That's why pawnpal draws its own arrow overlay, as `kit.html` does.
  - No promotion dialog and no built-in click-to-move; we build both.
  - Keyboard support is weak: arrow keys move a piece 25px per press.
- **Piece sets:** licenses come from [lila COPYING.md](https://github.com/lichess-org/lila/blob/master/COPYING.md).
  - **Compatible:** cburnett, merida and mono (GPLv2+), chessnut (Apache-2.0), kosal (CC BY 4.0), rhosgfx (CC0), spatial, celtic and fantasy (MIT).
  - **Not GPL-compatible:** sets under CC BY-NC-SA, including **horsey**, california, maestro, cardinal and staunty. They can't be relicensed under GPL. Like Lichess (AGPL), pawnpal ships horsey as a separately licensed asset.

## Open decisions

1. **Piece set: decided, horsey is the default.** It ships unmodified under its own CC BY-NC-SA 4.0 license, the way Lichess ships it. What that means:
   - The app's About screen and the README must credit cham and michael1241 and link the license.
   - pawnpal as a whole is no longer 100% free-licensed: those files can't be used commercially. Anyone distributing pawnpal commercially must delete `assets/pieces/horsey/` and switch the default to Friendly or Classic.
   - Edits to the horsey files must stay CC BY-NC-SA. We keep them byte-for-byte unmodified.
   - The release license check (spec 12) must allow exactly this folder and nothing else under NC terms.
   - This isn't legal advice.
2. **Age bands.** Keep the 9+ "older" band, or use one size for everyone.
3. **Animal avatars** are emoji placeholders. Final art should match Pip's flat style.
4. **Resolved:** specs 04, 05 and 07 now name the kit's annotations (solid blue better-move arrow, dashed orange threat arrow, coral ring with a "!" badge).
